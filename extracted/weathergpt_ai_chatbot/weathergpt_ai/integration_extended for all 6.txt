# WeatherGPT — Complete Final Integration Contract

**Version:** 1.0
**Project:** WeatherGPT
**Purpose:** Define exactly how all 6 members integrate their modules and how Flutter communicates with the backend.

---

# 1. Overall Architecture

```text
                         ┌──────────────────────┐
                         │      Flutter UI      │
                         │      Member 4        │
                         └──────────┬───────────┘
                                    │
                              HTTP / JSON
                                    │
                                    ▼
                         ┌──────────────────────┐
                         │      FastAPI         │
                         │   Integration Layer  │
                         └──────────┬───────────┘
                                    │
                 ┌──────────────────┼──────────────────┐
                 │                  │                  │
                 ▼                  ▼                  ▼
        ┌────────────────┐ ┌────────────────┐ ┌────────────────┐
        │ AI / Chatbot   │ │ Weather API    │ │ Risk Engine    │
        │ Member 1       │ │ Member 2       │ │ Member 3       │
        └───────┬────────┘ └───────┬────────┘ └───────┬────────┘
                │                  │                  │
                │                  │                  │
                └──────────────────┼──────────────────┘
                                   │
                                   ▼
                         ┌──────────────────────┐
                         │ Risk Map + Alerts    │
                         │ Member 5             │
                         └──────────────────────┘

                         ┌──────────────────────┐
                         │ Climate + Languages │
                         │ + Testing            │
                         │ Member 6             │
                         └──────────────────────┘
```

### Golden Rule

> **Flutter displays. FastAPI connects. AI interprets. Weather API provides weather. Risk Engine calculates risk. Simulation Engine calculates scenarios. Risk Map/Alerts visualizes warnings.**

No member should directly depend on another member's internal Python classes.

Communication happens through **JSON contracts**.

| Member | Module                           | Main Responsibility                            |
| ------ | -------------------------------- | ---------------------------------------------- |
| **1**  | AI / Chatbot                     | Intent, location, time, language, conversation |

| **3**  | Risk + Simulation                | Risk score and what-if calculations            |

# 3. Communication Architecture

All communication should eventually go through the FastAPI backend.

```text
Flutter
   │
   │ POST /chat
   ▼
FastAPI
   │
   ├──► Member 1: AI analysis
   │
   ├──► Member 2: Weather
   │
   ├──► Member 3: Risk / Simulation
   │
   ├──► Member 5: Alerts / Map
   │
   └──► Member 6: Language / Climate
   │
   ▼
Final JSON
   │
   ▼
Flutter
```

# 4. Base API URL

During development:

```text
http://127.0.0.1:8000
```

For Flutter running on an Android emulator, usually:

```text
http://10.0.2.2:8000
```

For a physical phone connected to the same Wi-Fi:

```text
http://YOUR-PC-IP:8000
```

Example:

```text
http://192.168.1.10:8000
```

For deployment:

```text
https://your-weathergpt-api.com
```

Flutter should store this as a configurable `BASE_URL`, not hard-code it throughout the application.

---

# 5. Common JSON Rules

Every module must follow these rules:

```text
JSON only
UTF-8
snake_case field names
null when information is unavailable
ISO dates where actual dates are returned
latitude/longitude as numbers
risk_score between 0 and 100
```

Never:

```text
"Chennai" when location is unknown
```

unless the user explicitly mentioned Chennai or it was established by conversation context/current-location functionality.

# 40. Conversation Memory

Every Flutter session must have a:

```text
session_id
```

Example:

```text
session-001
```

Conversation:

```text
User:
What's the weather in Chennai?

AI:
...

User:
What about tomorrow?

AI:
Tomorrow in Chennai...
```

Member 1 uses the existing session context.

### Important

If the user explicitly changes location:

```text
What's the weather in Mumbai?
```

the new location **overrides the previous Chennai location**.

---

# 41. Unified Final Response Schema

Every `/chat` response should ideally follow:

```json
{
  "success": true,

  "session_id": "session-001",

  "user_message": "...",

  "analysis": {},

  "weather": null,

  "risk": null,

  "simulation": null,

  "alerts": [],

  "climate": null,

  "response": "...",

  "error": null
}
```

This is the **main contract between FastAPI and Flutter**.

Flutter doesn't need to understand the internal modules.

---

# 42. Error Response

If something fails:

```json
{
  "success": false,

  "session_id": "session-001",

  "user_message": "What's the weather in Chennai?",

  "analysis": null,

  "weather": null,

  "risk": null,

  "simulation": null,

  "alerts": [],

  "climate": null,

  "response": "Sorry, I couldn't retrieve the weather information right now.",

  "error": {
    "code": "WEATHER_API_ERROR",
    "message": "Weather service unavailable"
  }
}
```

Recommended error codes:

```text
INVALID_REQUEST
INVALID_LOCATION
WEATHER_API_ERROR
RISK_ENGINE_ERROR
SIMULATION_ERROR
AI_ERROR
LANGUAGE_ERROR
INTERNAL_ERROR
```

# 51. 🚨 Critical Rules for Your Team

### Rule 1

**Never calculate risk inside Member 1.**

Member 1 only extracts:

```text
"What if rainfall = 100 mm?"
```

Member 3 calculates what that means.

---

### Rule 2

**Never put weather values inside Gemini as invented values.**

Gemini receives actual weather data from Member 2.

---

### Rule 3

**Flutter does not directly call Gemini.**

```text
Flutter → FastAPI → AI
```

not:

```text
Flutter → Gemini
```

---

### Rule 4

**Flutter does not directly call the weather provider.**

```text
Flutter → FastAPI → Weather module
```

---

### Rule 5

**No hard-coded Chennai/Mumbai defaults.**

If location is unknown:

```json
"location": null
```

or use an explicitly supplied current-location mechanism.

---

### Rule 6

**Session ID must remain consistent.**

```text
Flutter
session-001
     ↓
FastAPI
session-001
     ↓
AI
session-001
```

---

### Rule 7

**Don't depend on another member's source code.**

Depend on:

```text
JSON contract
```

not:

```text
Python class/function
```
